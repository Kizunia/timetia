# Milestone 2: Platform Conventions

- **Type:** spec
- **Module:** platform
- **Status:** draft
- **Owner:** ishanKulkarni13
- **Last updated:** 2026-11-08

> **Implementation:** planned. No JPA, migrations or API conventions exist.

## Scope

The conventions every module relies on, each proven by a test: persistence, tenancy, API behavior, events and jobs. Decisions: [ADR 0012](../../decisions/0012-flyway-managed-schema-evolution.md), [ADR 0028](../../decisions/0028-tenant-ready-schema.md), [ADR 0031](../../decisions/0031-transactional-outbox-and-locked-jobs.md), [ADR 0033](../../decisions/0033-uuidv7-identifiers.md), [ADR 0034](../../decisions/0034-soft-delete-with-retention-purge.md), [ADR 0043](../../decisions/0043-http-api-conventions.md).

## Completion criteria (proposed; rewritten on 2026-11-08 after the second decision round, awaiting owner approval)

- JPA is added and Hibernate does not create or alter the schema. Migrations use the naming and per-module locations in [schema migrations](../../architecture/data/schema-migrations.md), and a Testcontainers MySQL test applies all of them to an empty database ([ADR 0017](../../decisions/0017-testcontainers-mysql-for-persistence-tests.md)).
- UUIDv7 identifiers stored as `BINARY(16)`, audit columns and optimistic locking work, with tests (check OQ-41).
- The tenant context and `@TenantId` enforcement work, and cross-tenant isolation tests pass ([ADR 0028](../../decisions/0028-tenant-ready-schema.md)).
- The soft-delete conventions, including filtering, uniqueness and purge, are implemented and tested ([ADR 0034](../../decisions/0034-soft-delete-with-retention-purge.md)).
- The error format (Problem Details with `code`, `traceId` and `errors`), the status mapping, paging, sorting and filtering follow [API conventions](../../architecture/api/conventions.md) and are covered by API tests.
- The OpenAPI description is generated by springdoc, written to the committed `openapi.json`, and the frontend client is generated from it; CI fails when the file is stale.
- The outbox (Spring Modulith event publication registry) and lock-protected jobs work: retry, idempotency, failed-event view, tenant and trace propagation ([ADR 0031](../../decisions/0031-transactional-outbox-and-locked-jobs.md), [ADR 0039](../../decisions/0039-spring-modulith-module-boundaries-and-outbox.md)).
- The decision point exists with `can`, `scopeFor`, `@RequiresPermission` and `@NoAuthorization`, and its ArchUnit rule runs ([ADR 0044](../../decisions/0044-authorization-enforcement-conventions.md)).
- The `audit` module records entries in the caller's transaction by user ID only, and the retention purge works ([ADR 0046](../../decisions/0046-audit-log-design.md)).
- A reference example keeps entity, application model and API type apart, using hand-written mappers with tests ([ADR 0005](../../decisions/0005-hand-written-model-mappers.md)).
- All of the above pass in CI ([verification standard](../../engineering/testing/verification-standard.md)).
