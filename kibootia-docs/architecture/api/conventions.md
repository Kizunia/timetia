# API Conventions

- **Type:** spec
- **Module:** platform
- **Status:** draft
- **Owner:** ishanKulkarni13
- **Last updated:** 2026-11-10

> **Implementation:** verified (CI run 42605511477, 2026-11-09). `platform.errors` and `platform.web` implement the error shape, status mapping and paging; `notes` and `failed-events` are the first resources; `backend/openapi.json` is generated by `OpenApiContractIT` and the TypeScript client from it. Swagger UI is a management endpoint, exposed by `pnpm dev` only.

Decision: [ADR 0043](../../decisions/0043-http-api-conventions.md). Related: [ADR 0042](../../decisions/0042-bff-api-proxy-and-csrf.md) (how the browser reaches the API), [ADR 0044](../../decisions/0044-authorization-enforcement-conventions.md) (authorization).

## Purpose

Fix how the HTTP API behaves, once, for every module. Global conventions live in the `platform` module; business behavior stays with the owning module.

## Contract

- **Code-first:** springdoc-openapi (v3 line, exact version pinned at implementation) generates the OpenAPI description from controllers and DTOs.
- A test writes it to a committed `openapi.json`; CI fails when the committed file is out of date. API changes are therefore visible as a diff in every pull request.
- The frontend's typed client is generated from that file ([frontend](../frontend.md)).
- DTOs, never entities, form the contract ([model separation](../data/model-separation.md)).
- Swagger UI is enabled locally and disabled in production by default.

## URLs and formats

- Everything under `/api/v1/`. Plural kebab-case nouns: `/api/v1/users/{id}`, `/api/v1/roles`.
- Actions that are not plain create, read, update or delete are sub-resources: `POST /api/v1/users/{id}/disable`.
- JSON in camelCase; timestamps ISO-8601 in UTC; identifiers as UUID strings.
- A new major version only for a breaking change that matters to non-browser clients.

## Errors

RFC 9457 Problem Details with Kibootia extensions:

```json
{
  "type": "about:blank",
  "title": "Validation failed",
  "status": 400,
  "detail": "The request contains invalid fields.",
  "code": "platform.validation_failed",
  "traceId": "4bf92f3577b34da6a3ce929d0e0e4736",
  "errors": [
    { "field": "email", "code": "invalid_format", "message": "must be a valid email address" }
  ]
}
```

- `code` is stable and machine-readable, `<module>.<reason>`. The frontend chooses its message from it.
- `traceId` lets a user's report be found in logs and traces.
- No stack traces, infrastructure details, secrets or tokens in any error response or log.

## Status codes

| Situation | Status |
|---|---|
| Malformed request or failed validation | 400, with `errors` |
| Missing or invalid token | 401 |
| Authenticated but not allowed, including email not verified (`platform.email_not_verified`) and a disabled or deleted account (`identity.account_disabled`) | 403 |
| Not found, or exists but the caller may not see it (another tenant, no view permission) | 404 |
| Concurrent-edit conflict (`version` mismatch), duplicate, or a business-state rule such as removing the last administrator | 409 |
| Upload too large / unsupported type | 413 / 415 |
| Rate limited | 429 with `Retry-After` |
| A system the call depends on, such as Keycloak, cannot be reached | 503 (`platform.service_unavailable`) |
| Unexpected failure | 500, generic message with `traceId` |

## Lists

- Response: `{ "items": [...], "page": { "number", "size", "totalElements", "totalPages" } }`.
- Parameters: `page`, `size` (default 20, maximum 100), `sort=field,asc|desc`. Sortable fields are an allow-list per endpoint.
- Filters are named query parameters per endpoint (`?status=active&q=ann`). There is no generic filter language.
- Deleted records are not listed by default. Where they can be listed (`GET /api/v1/notes?deleted=true`), that is an administrative view: it needs the permission to restore records, lists everyone's, and is `403` without it.
- Offset paging is the default; keyset paging is documented for large tables.
- What a caller may see in a list is decided by the authorization scope ([authorization](../identity/authorization.md)).

## Other rules

- The backend validates all input; client-side validation never replaces it.
- No CORS policy for browser traffic; browsers reach the API only through the Next.js proxy.
- Sensitive endpoints are rate limited per user and per application instance (invitations, administrative actions, asking for the verification email again, uploads) with Bucket4j, 429 and `Retry-After` when the allowance is used up; production also limits at the edge. Keycloak's brute-force detection covers login. The limits are `kibootia.rate-limit.limits.<category>.capacity` and `.period`.

## Files

Decision: [ADR 0029](../../decisions/0029-s3-object-storage-contract.md), [ADR 0051](../../decisions/0051-milestone-4-implementation-decisions.md). Verified (CI run 42873216224, 2026-11-10).

- An upload is `multipart/form-data` with one part named `file`, sent with `PUT` to the resource it belongs to (`/api/v1/me/avatar`, or `/api/v1/notes/{id}/attachment` for a file that belongs to a record). The answer is the changed resource, not the file.
- A file is shown from an endpoint of its own (`GET /api/v1/users/{id}/avatar?size=SMALL|LARGE`), never from a public address, so the permission is checked on every view. The response has a fixed `Content-Type`, `X-Content-Type-Options: nosniff`, a `Content-Security-Policy` of `default-src 'none'; sandbox`, an `ETag`, and `Cache-Control: private, no-cache`; a request with a matching `If-None-Match` is answered 304 after the check.
- Upload errors: 413 `files.too_large` (the category's limit, 5 MB for an avatar) or `platform.payload_too_large` (above the multipart ceiling), 415 `files.unsupported_type` (decided from the bytes), 400 `files.invalid_image` (damaged, empty, or over 40 megapixels), 429 with `Retry-After`, 503 when the storage server cannot be reached, 404 `files.disabled` when the module is switched off.
- A resource that has a file carries a nullable version of it (`avatarVersion`, `attachmentVersion`), the file's ID. It changes with every upload and is what the interface puts in the image address to refresh a cached copy.
- A file that belongs to a record follows the record: it is shown at `GET /api/v1/notes/{id}/attachment?size=PREVIEW|FULL`, whoever may see the record may see it, whoever may change the record may attach, replace or remove it, a record the caller may not see answers `404` for its file too, and a record with no file answers `404` `notes.attachment_not_found`. Attaching a file does not change the record's `version`. A rendition can keep the whole image in proportion (the longest side is the size, never enlarged) or be cut to a square, as the category says.

## Testing

API tests cover each endpoint, including its error cases ([verification standard](../../engineering/testing/verification-standard.md)): `ApiConventionsIT` raises every row of the status table through the real filter chain and checks that no error leaks an internal detail; `NotesApiIT` and `FailedEventsApiIT` cover the resources; `OpenApiContractIT` checks the description.

## Changing the API

After adding or changing an endpoint, run `./mvnw verify` in `backend/`: `OpenApiContractIT` rewrites `backend/openapi.json`. Then run `pnpm --filter kibootia-frontend api:generate` to regenerate `frontend/src/lib/api/schema.gen.ts`. Commit both with the change. CI fails when either file is stale, so a reviewer always sees the API change as a diff.

Swagger UI and the raw description are served on the management port only (`http://localhost:8090/actuator/swagger-ui`, `/actuator/openapi`), and only when `management.endpoints.web.exposure.include` names `openapi` and `swaggerui`. `pnpm dev` does that; the default and production expose health alone, and the API port serves neither.
