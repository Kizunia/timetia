# 0033 UUIDv7 identifiers

- **Type:** adr
- **Module:** platform
- **Status:** accepted
- **Owner:** ishanKulkarni13
- **Last updated:** 2026-10-28

> **Implementation:** planned.

## Context

The identifier strategy was open (OQ-27). Events, outbox rows and stored objects reference records before and after they are saved, and identifiers appear in URLs.

## Decision

Records use **UUIDv7** identifiers generated by the application and stored as `BINARY(16)`. They cannot be guessed, are available before the row is saved, and are time-ordered, which keeps MySQL index inserts efficient. Support for generating them in the Hibernate version in use must be verified before the first table is built.

## Alternatives considered

| Alternative | Why not chosen |
|---|---|
| BIGINT auto-increment | Guessable, assigned only on insert, awkward when merging tenants or data |
| Random UUIDv4 | Random order fragments the primary index as tables grow |

## Consequences

16 bytes per key and identifiers that are harder to read when debugging.

## Status

accepted. Resolves the identifier part of OQ-27.
