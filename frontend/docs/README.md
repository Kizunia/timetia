# Frontend docs

Everything an engineer or AI agent needs to build the Timetia screens and the backend additions they depend on, without
reading the whole repository first. The docs are written from the code as it stood on 2026-11-16 (commit `88a8b14`); where
a doc names a class, a path or a field, it exists unless the doc says **NEW**.

## What Timetia is, in one paragraph

A college's weekly timetable is published once per term. Teachers then need to change single lectures: move one
(reschedule), cancel one, hand one to a colleague (substitute), swap with a colleague (exchange), add one (extra), or move
a weekly lecture for the rest of the term (permanent change). Each change is a **ticket**: it is checked for conflicts,
optionally reviewed by an HOD or a class/batch representative, and then **applied** to the **live timetable** that
everyone reads. Representatives can open **issues** asking for a change. Everyone affected gets an in-app
**notification**. The backend for all of this exists; the web app has no screens for it yet.

## Commands (PowerShell, from the repository root)

```powershell
pnpm install
pnpm bootstrap                                    # once: writes .env with secrets and demo passwords
pnpm infra:up                                     # MySQL, Keycloak, Mailpit, Adminer (Docker Desktop must be running)
$env:MAVEN_ARGS = '-Dmaven.compiler.release=21'   # only when no JDK 25 is installed
pnpm dev                                          # backend :8080 and web app :3470
pnpm reset                                        # wipe database and Keycloak, keep .env

pnpm --filter kibootia-frontend api:generate      # regenerate src/lib/api/schema.gen.ts from backend/openapi.json
pnpm --filter kibootia-frontend lint
pnpm --filter kibootia-frontend typecheck
pnpm --filter kibootia-frontend test              # Vitest
pnpm --filter kibootia-frontend build
pnpm --filter kibootia-frontend test:e2e          # Playwright, needs the whole stack running
```

Backend tests: see [backend-guide.md](backend-guide.md), section "Running".

## Hard rules for agents

1. Load the `shadcn` skill (`.agents/skills/shadcn`) before adding or composing a UI component. On a fresh clone install it with `pnpm dlx skills add shadcn/ui`.
2. Never edit `frontend/src/lib/api/schema.gen.ts` or `backend/openapi.json` by hand. Regenerate (backend-guide.md, "After an API change").
3. Never touch the sign-in/BFF code: `frontend/src/lib/bff/`, `src/lib/session.ts`, `src/lib/oidc.ts`, `src/app/auth/`, `src/app/api/`. `src/proxy.ts` is edited only to add a route to its `matcher` (architecture.md, "Registering a feature").
4. Do the phases in order. Each phase's "Prerequisites" must hold before its first change.
5. Do not commit or push unless the person you work for asks.
6. Delivery over polish. If time is short, follow the cut order in [plan.md](plan.md).
7. Known baseline: 15 frontend unit tests fail before any Timetia change (`tests/unit/avatar.test.tsx`, `import-screen.test.tsx`, `note-attachment.test.tsx`). They are not yours until Phase 3. A new failure is yours.
