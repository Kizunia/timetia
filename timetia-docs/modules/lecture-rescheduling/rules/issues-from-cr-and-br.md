# Issues from CR and BR

- **Type:** rules
- **Module:** lecture-rescheduling
- **Status:** review
- **Owner:** ishanKulkarni13
- **Last updated:** 2026-10-27

Requests from the student side work **exactly like GitHub issues**. This replaces the spec rule that a CR-initiated extra lecture "needs the faculty's acceptance" ([module spec](../../lecture-rescheduling.md), section 8.4). See [issue](../../../shared/glossary/issue.md).

## How it works

1. A **CR** (theory) or **BR** (labs and tutorials) opens an issue describing what the class wants, for example "extra DBMS lecture before the test".
2. They can **mention or link faculty** in it.
3. Each mentioned faculty receives a notification that an issue mentions them.
4. The faculty reads it. If they agree, they raise the normal extra-lecture ticket themselves. If not, they ignore it.

## Rules

| Rule | Outcome |
| --- | --- |
| Who can open an issue | **Only CR and BR**, within their scope. Ordinary students cannot. |
| Does it change the timetable | **No.** It is only a request. Only a ticket changes the timetable. |
| Acceptance step | None. A mentioned faculty is only notified. |
| Linking | An issue can be linked to the ticket that answers it, as a GitHub issue links to a pull request. |
| Closing | The **opener** or **any mentioned faculty** can close it. |
| Expiry | Issues **do not expire** for now. |

Replies and labels are not part of this version. This feature is low priority.
