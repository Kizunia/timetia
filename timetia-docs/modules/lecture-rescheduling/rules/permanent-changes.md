# Permanent changes

- **Type:** rules
- **Module:** lecture-rescheduling
- **Status:** review
- **Owner:** ishanKulkarni13
- **Last updated:** 2026-10-27

A permanent change repeats every week from a date onward. It always needs the **HOD** ([approval model](approval-model.md)).

- **For now the module publishes the permanent change itself.** Once the HOD approves, it applies as a recurring change in the module's own change overlay, from the chosen date.
- Version 1 is standalone, so there is no ERP to write to. The base timetable is unchanged, and the module emits the usual events for the affected occurrences.
- The owner marked this **"for now"** and expects it may change.

## ERP sync

Decided 2026-11-06: **there is no sync between the module and the ERP for now**, and the ERP gives no API, so timetable data is seeded manually. The module is standalone in version 1, so the earlier worry that the module and the ERP show different weekly timetables does not apply yet. See [open questions](../open-questions.md).
