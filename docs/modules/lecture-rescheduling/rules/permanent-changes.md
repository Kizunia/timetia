# Permanent changes

- **Type:** rules
- **Module:** lecture-rescheduling
- **Status:** review
- **Owner:** ishanKulkarni13
- **Last updated:** 2026-10-27

A permanent change repeats every week from a date onward. It always needs the **HOD** ([approval model](approval-model.md)).

- **For now the module publishes the permanent change itself.** Once the HOD approves, it applies as a recurring change in the module's own change overlay, from the chosen date.
- It is **not written into the ERP**. The ERP base timetable is unchanged, and the module emits the usual events for the affected occurrences.
- The owner marked this **"for now"** and expects it may change.

## Tension to resolve later

The module spec says the module never writes to the ERP and never owns the base timetable. A permanent change kept only in the overlay means the module and the ERP show different weekly timetables until the ERP owner publishes a matching version. Reconcile this when the ERP integration is designed. See [open questions](../open-questions.md).
